Features

Everything a terminal should do. Nothing it shouldn't.

Termdock keeps the connections you use every day one click away, and gets out of the way once you're in.

Favorites bar

Always visible. One click opens a connection in a new tab; drag to reorder, right-click to edit, CtrlShift1…9 opens the first nine.

Split panes

Server A on the left, server B on the right. Split as often as you like, put open tabs side by side without reconnecting, drag dividers, jump with Alt←↑→↓.

SFTP file browser

Files next to the terminal, on the same connection: no second login. Drag & drop, whole-folder transfers through a queue, a view that follows cd, remote editing with F4 (uploaded at every save, asking first if the server's copy changed), even as another user after sudo -iu, whose password is never saved.

Security

Paranoid by default.

SSH implemented in memory-safe Rust: no external ssh process, no intermediate shell, no secrets on disk. Modern cryptography first, legacy algorithms left out, and the server treated as untrusted.

Host keys, verified first

The fingerprint is checked before any authentication. A changed key is refused, with no "connect anyway" button. ~/.ssh/known_hosts is read too, with hashed entries, wildcards and @revoked.

Secrets stay in the keychain

Passwords are saved only if you ask, only in the OS keychain, wiped from memory after use and never sent to the UI.

Least-privilege app

Strict CSP, every IPC command allow-listed, no file system or shell plugins, no innerHTML.

Signed, audited releases

Updates are verified against a key built into the app, never downgraded. CI runs cargo audit, npm audit and end-to-end tests against OpenSSH.

The server can't reach back

Channels the server tries to open on its own (X11, agent, sessions, direct connections) are refused, web links it prints open only on Ctrl+click after a confirmation that shows where they really go, and downloaded files are marked so SmartScreen or Gatekeeper checks them before they run.

Safe paste, focused prompts

Pasted text loses control characters, several lines are shown in a preview first with invisible characters marked, and a password prompt from a background tab waits until you look at it.

Roadmap

The road to 1.0.

What must land before Termdock 1.0, tracked in the open as a GitHub milestone. Other ideas can still arrive in 1.x.

  1. #33

    Signed builds on macOS and Windows

    Developer ID signing and notarization on macOS, Authenticode signing on Windows, so Gatekeeper and SmartScreen stop warning at the first launch.

  2. #34

    ARM packages for Windows and Linux

    Native installers for Windows on ARM laptops, and AppImage, .deb and .rpm for ARM Linux such as the Raspberry Pi, with in-app updates on both.

  3. #39

    FIDO security keys

    Log in with ed25519-sk and ecdsa-sk keys on a YubiKey or similar, from a file or the agent, with a clear message when the key must be touched.

  4. #37

    Stored data that never breaks

    Tests that load connections, settings and backups written by older versions, so every update keeps your setup as it was.

  5. #36

    A fixes-only stabilization period

    A feature-frozen release candidate used daily on Windows, macOS and Linux for a few weeks, with only fix releases until no blocking bug is open.

  6. v1.0.0

    Termdock 1.0

    Tagged once the stabilization period ends, with what 1.0 promises (stored data, settings, backup format) written down in the README and changelog.

FAQ

Good questions.

Is Termdock really free?

Yes. It is open source under the MIT license, with no account to create and no paid tier. If it saves you time, you can support its development on Ko-fi.

Where are my passwords stored?

Nowhere, unless you ask. If you choose to remember one, it goes into your operating system's keychain (Windows Credential Manager, macOS Keychain or Secret Service on Linux), never into a file. Changing a connection's host, port, user or authentication method deletes it.

Can I use my existing SSH keys, agent and config?

Yes. Termdock works with ssh-agent, the Windows OpenSSH agent and Pageant, private keys (encrypted too), passwords and keyboard-interactive / 2FA logins, reads your ~/.ssh/known_hosts, and imports connections from ~/.ssh/config with a preview first.

How do updates work?

At start and once a day Termdock checks for a new version, and installs it only after you confirm. Every package is verified against the signing key built into the app and must be signed for the version it claims, so tampered or older packages are rejected. You can turn the check off in Settings. deb and rpm installs are just notified, so your package manager stays in charge.

Does it replace PuTTY or Windows Terminal?

It covers both jobs: a modern terminal for local shells (PowerShell, cmd, WSL, Git Bash, bash, zsh…) and a connection manager for SSH with favorites, SFTP, tunnels and jump hosts, in the same window.

Can I move my setup to another computer?

Yes. Settings → General → Export… saves connections, favorites, layouts, snippets and settings in one JSON file; on the other computer Import… shows what the backup holds, then adds only what is new or replaces the current configuration. Passwords, keys and host keys are never included, so you enter them again there.
